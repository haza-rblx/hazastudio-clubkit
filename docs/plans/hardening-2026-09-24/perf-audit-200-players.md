# 200-player performance audit (read-only agent, 2026-09-24). S/ C/ Sh/ = server/client/shared roots.
Dense = packed floor, most players within the 55-stud overhead range.

Most serious: (1f) server keeps a deep copy of the last overhead sent per viewer–subject pair (DeltaCompressor, DEEP_DELTA_NESTED=true, Config 4170; Sh/Utils/DeltaCompressor.luau:73-78) → up to 40k copies, ~40–100 MB when dense; cleanup(prefix) (176-181) scans all keys per leave → O(n²) per leave. (3a) XP tick every 10 s writes DataStore and rebroadcasts overhead to k viewers. (3c) MovementGuard (S/Init/MovementGuard.luau:323-343) samples every player in ONE frame every 0.5 s; sampleCharacter builds an exclude list of every character (151-156) + new RaycastParams + 2–3 raycasts → O(n²) per tick in one frame. (2c) ReliabilityV2 ≈ 400 POST per donation at n=200. (6f) NON-DONORS never fill cashDonatedCache, so each 10 s rebuild re-triggers fetchDonorCashProfile (DonationService 2015-2060) → with DONOR_PROFILE_CACHE_TTL=45 ≈ 1 GET per 45 s per non-donor ≈ 260 req/min server-wide vs 500 limit.
