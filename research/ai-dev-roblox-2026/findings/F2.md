# F2: Frontier coding models and agentic coding tools in the last 12 months (Oct 2025 – Oct 2026): what current top coding models changed for repo-scale, long-horizon agentic coding; notable capability jumps and feature developments in agentic IDEs/CLIs that changed practitioners' daily workflows.

## Findings

### [1] Claude Opus 4.5 (released Nov 24, 2025) is positioned by Anthropic as the best coding/agent model and ships with a new "effort parameter" that trades cost vs. capability, enabling far cheaper agent runs at medium effort.
- quote: "With our new effort parameter on the Claude API, you can decide to minimize time and spend or maximize capability. Set to a medium effort level, Opus 4.5 matches Sonnet 4.5's best score on SWE-bench Verified, but uses 76% fewer output tokens."
- url: https://www.anthropic.com/news/claude-opus-4-5
- source_type: primary
- published: 2025-11-24
- confidence: high

### [2] Opus 4.5 is explicitly optimized for long-horizon agentic work, with customers reporting 30-minute autonomous coding sessions, multi-codebase / multi-agent refactors, and up to 65% fewer tokens at equal-or-better quality than prior models.
- quote: "Claude Opus 4.5 handles long-horizon coding tasks more efficiently than any model we've tested. It achieves higher pass rates on held-out tests while using up to 65% fewer tokens" (Sourcegraph, in Anthropic announcement)
- url: https://www.anthropic.com/news/claude-opus-4-5
- source_type: primary
- published: 2025-11-24
- confidence: high

### [3] GPT-5.1-Codex-Max (released Nov 19, 2025) introduced "compaction" — the first OpenAI model natively trained to operate across multiple context windows — enabling project-scale refactors and multi-hour agent loops without losing coherence.
- quote: "It's our first model natively trained to operate across multiple context windows through a process called compaction, coherently working over millions of tokens in a single task. This unlocks project-scale refactors, deep debugging sessions, and multi-hour agent loops."
- url: https://openai.com/index/gpt-5-1-codex-max/
- source_type: primary
- published: 2025-11-19
- confidence: high

### [4] OpenAI reports Codex-Max can work independently for 24+ hours on a task, automatically compacting its context window as it fills, and cites internal data that 95% of OpenAI engineers use Codex weekly and ship ~70% more PRs.
- quote: "In our internal evaluations, we've observed GPT-5.1-Codex-Max work on tasks for more than 24 hours... internally, 95% of OpenAI engineers use Codex weekly, and these engineers ship roughly 70% more pull requests since adopting Codex."
- url: https://openai.com/index/gpt-5-1-codex-max/
- source_type: primary
- published: 2025-11-19
- confidence: medium  (vendor self-report on PR metric)

### [5] Practitioners confirm Opus 4.5 became the default "driver" model for daily agentic coding, with some burning >€1000/week in tokens; some report a full refactor of a 650-file monorepo done in ~2 days using Claude Code (Opus 4.5) + Codex CLI (GPT-5.2 xhigh) with the model writing essentially all implementation code.
- quote: "I built this in ~2 days using Claude Code (Opus 4.5) and Codex CLI (GPT-5.2 xhigh). The entire Svelte parser, TSX transformer, diagnostics engine, and CLI were written entirely by AI. I focused on architecture decisions and testing against real codebases while the models handled the implementation."
- url: https://news.ycombinator.com/item?id=46478789 (Show HN: I built a 30x faster svelte-check in 2 days with AI)
- source_type: community
- published: 2026-01-03
- confidence: high

### [6] Fast verification loops (sub-2-second type-checks / builds) materially change how effective coding agents are: practitioners explicitly built faster checkers so agents can iterate and self-correct in real time, because waiting 40s for a check "kills the feedback loop."
- quote: "When agents write code, they need to verify it works, and waiting 40 seconds for type-checking kills the feedback loop. With 1-2 second checks, agents can iterate much faster and catch their own mistakes immediately on our large and growing production SvelteKit codebase."
- url: https://news.ycombinator.com/item?id=46478789
- source_type: community
- published: 2026-01-03
- confidence: high

### [7] Agent memory / persistent cross-session context became a solved-and-productized problem in 2026: tools like the "draft" Claude Code plugin use a session-init hook to inject a ~5k-token compressed summary of product/company context, plus an inference-driven "/draft:learn" subagent that decides what's worth persisting — addressing the "every new session starts from scratch" pain for solo devs.
- quote: "on every session start, a hook fires and injects a structured context summary into claude's working memory... the main claude agent reads its instructions and decides when something is worth persisting... over time, claude accumulates enough context to flag contradictions."
- url: https://github.com/idodekerobo/draft-cli-plugin (via Show HN, story 48080538)
- source_type: community
- published: 2026-05-10
- confidence: medium

### [8] Orchestrating multiple agents (rather than one agent) became the dominant practitioner pattern in 2026: dedicated tools emerged (e.g., "Mission Control" daemon that auto-spawns Claude Code sessions from a task queue with retries/concurrency, and DoorDash's open-source "Agentic Orchestrator" TUI that runs deterministic phase gates over Claude Code/Codex/OpenCode) because hand-feeding multiple agents was unmanageable.
- quote: "The killer feature is the autonomous daemon. It runs in the background, polls your task queue, spawns Claude Code sessions automatically, handles retries, manages concurrency, and respects your cron-scheduled work." ... "this is deterministic orchestration on top of undeterministic agents... in my setup I like to mix and match different agents/models for different phases (eg: claude/opus4.7 for planning, opencode/glm5.2 for implementing, codex/gpt5.5 for reviewing)."
- url: https://github.com/MeisnerDan/mission-control ; https://github.com/doordash-oss/agentic-orchestrator
- source_type: community
- published: 2026-02-26 / 2026-06-30
- confidence: medium

### [9] A counter-trend emerged among practitioners in mid-2026: skepticism that multi-agent orchestration is over-engineered relative to giving a single agent a programmable environment. The Lazarus agent gives the model exactly one tool (a persistent Python runtime) plus self-compression of context, and matched reported GPT-5.5-in-Codex results on FrontierSWE long-horizon tasks with a single tool-calling loop.
- quote: "current models are much better at writing code than coordinating fleets of agents. Agent orchestration consumes context, introduces extra modes of failure... Using GPT-5.5 at medium reasoning effort, Lazarus achieved scores comparable to reported GPT-5.5 in Codex with xhigh reasoning."
- url: https://github.com/ExpressGradient/lazarus (Show HN, story 48416473)
- source_type: community
- published: 2026-06-05
- confidence: medium

### [10] Open-weight models closed much of the agentic-coding gap by mid-2026: DeepSeek V4 (Apr 2026) claims SOTA among open-source on agentic coding, was explicitly trained against Claude Code / OpenClaw / OpenCode / CodeBuddy harnesses, offers 1M-token context via sparse attention, and is priced at $1.74/$3.48 per M tokens (Pro) — a fraction of frontier closed models, making high-usage agent loops dramatically cheaper.
- quote: "Agent capabilities got a dedicated upgrade. Trained specifically against Claude Code, OpenClaw, OpenCode, and CodeBuddy. V4-Pro is now the recommended model for any agentic / coding workflow... DeepSeek-V4-Pro: $1.74 / $3.48 per M input/output tokens."
- url: https://news.ycombinator.com/item?id=47885230 (DeepSeek V4 breakdown)
- source_type: community
- published: 2026-04-24
- confidence: low-medium  (vendor claims relayed via community; not independently verified)

### [11] Practitioners report the workflow that actually works is: write a detailed spec up front, and on failure revise the spec rather than iteratively prompt-fix; agent quality still varies enough that even top models (Opus 4.5 in Cursor) can fumble mechanical refactors — the leverage is in spec quality and fast verification, not the model alone.
- quote: "I'm writing detailed specs. On failure, I adjust the initial spec, rather than go down the spiral of asking for many adjustments... It was trying to action the refactor by writing some Python one-liners to edit the file, in an extremely clumsy way."
- url: https://news.ycombinator.com/item?id=46598278 (Ask HN: Why are AI coding agents not working for me?)
- source_type: community
- published: 2026-01-13
- confidence: medium
